# 회신 — `fin-ticket-1.0.0.zip` 질문 3건

기술 판단만 담는다. 답마다 확인용 명령을 같이 적었으니 그대로 돌려 봐도 된다.

## 1. `PROCESS_STEPS` — 둘 중 고르지 말고 **셋째 길**로

제시한 두 선택지 말고 더 나은 길이 있다. **`type` 은 `FEATURE_GRID` 로 두고, 그 렌더러를
4단계 카드 + 커넥터로 그린다.**

핵심은 이것이다 — **계약은 `type` 과 `config` 키를 정할 뿐 마크업을 정하지 않는다.**
`src/components/sections/FeatureGridSection.tsx` 는 **그쪽 소스**다. 우리 예제가 6칸 아이콘
그리드로 그린 것은 그 예제의 선택이지 계약이 아니다. 그 파일을 4단계 카드로 다시 써도
계약은 그대로 지켜진다.

`FEATURE_GRID` 의 config 모양이 마침 4단계와 맞는다:

```
FEATURE_GRID | title?, items[{icon?, title, body?}]
```

확인: `node -p "require('@zalkera/client').SECTION_CONTRACT.find(s=>s.type==='FEATURE_GRID')"`
그리고 각 키의 뜻은 `node_modules/@zalkera/client/llms.txt` 의 어휘 표에 있다.

- 단계 하나 = `items` 한 칸. 제목은 `title`, 설명은 `body`, 아이콘은 `icon`(선택).
- **단계 번호는 config 에 넣지 마라** — 배열 순서(`index`)에서 뽑아 그린다. 번호를 데이터로
  들고 있으면 순서를 바꿀 때 두 곳을 고쳐야 한다.
- 커넥터는 순수 마크업이다. 항목 사이에 그리면 된다.

**왜 자유 영역보다 이쪽이 나은가.** 자유 영역으로 옮기면 그 문구가 `content/pages/*.json` 이
아니라 tsx 안으로 들어간다. 그러면 나중에 "3단계 설명 문구 바꿔줘"가 **파일 하나를 여는
대신 컴포넌트 트리를 탐색하는 일**이 된다. 디자인은 지키면서 그 경로도 지키는 것이
`FEATURE_GRID` + 자기 렌더러다.

**자유 영역이 맞는 경우도 있다** — 그 블록이 `items[{icon?, title, body?}]` 로 표현되지
않는 형태(예: 단계마다 이미지·링크·표가 붙는다)면 억지로 맞추지 말고 컴포넌트를 새로 써서
`src/app/page.tsx` 에서 직접 부르면 된다. 어휘는 보장의 **바닥이지 천장이 아니다.**

**하지 말 것**: 어휘에 없는 `type` 을 그대로 두는 것. 렌더러가 조용히 건너뛰어 화면에서
그 블록만 사라지고 로그도 안 남는다.

## 2. 이미지 2건 — **옵션 B(`asset` 키 삭제)를 권한다**

승인된 디자인이 폴백 일러스트라면 그게 정답이다. 실물 이미지를 넣으면 할 일이 늘어난다.

**옵션 B 로 갈 때**: `content/pages/home.json`·`about.json` 의 해당 섹션에서 `asset` 키를
지운다. 값을 `""` 나 `null` 로 두지 말고 **키째로** 지운다.

**옵션 A(실물을 넣는다)를 고를 때 따라오는 것** — 검수에서 이 둘을 본다.

- 파일은 `public/images/` 아래에 두고 콘텐츠에는 레포 루트 절대 경로로 적는다
  (`"asset": "/images/hero.png"`). `//` 시작·`\`·`..` 구간은 반려된다.
- **이미지가 든 zip 은 `.zalkera/ASSETS-LICENSE.md` 가 없으면 납품 검수에서 반려된다.**
  파일별로 출처와 라이선스를 적는다.

**원본 사이트 이미지를 그대로 쓸 수 있는지는 우리가 답할 수 없다.** 그 사이트 자산의
권리 관계는 발주하신 쪽이 확인할 문제이고, 확인한 결과를 위 라이선스 파일에 적는 것이
곧 그 답변이다. **권리를 확인하지 못한 이미지는 넣지 마라** — 그 경우 옵션 B 가 답이다.

## 3. `AGENTS.md` · `README.md`

### `AGENTS.md` — 예제 레포 **루트본을 복제하지 마라**

그 문서는 우리 레포를 고치는 에이전트용이라 우리 레포에만 있는 좌표를 가리킨다. 고객 트리에
그대로 두면 검사기가 죽은 좌표로 반려한다.

```
❌ [D1] AGENTS.md 가 없는 파일을 가리킵니다: `spec/storefront-spec.md`
```

재현: 그 파일을 트리 루트에 복사하고 `npx zalkera-validate . --gate`

**정본은 시작 소스 팩 zip 안의 `AGENTS.md` 다.** 그건 고객 트리 형상으로 쓰여 있고 검사도
통과한다(같은 트리에서 D1 0건). 그것을 바탕으로 삼는다.

바탕으로 삼은 뒤 **그쪽 트리에 없는 것의 좌표를 지운다.** 그 문서 자체가 그 규율을 적고
있다 — 안 쓰는 능력의 파일을 지웠으면 문서의 그 행도 같이 지우라는 것이고, 안 지우면
`[D1]` 이 난다. 쇼핑몰·예약·게시판을 안 쓰는 랜딩 페이지면 해당 표의 행들이 그 대상이다.

### `README.md` — 새로 쓴다

받는 사람이 **무엇을 어떻게 돌리는지** 아는 자리다. 팩 zip 의 `README.md` 를 뼈대로
쓰되 내용은 그 사이트 것으로 바꾼다. 최소한 이 셋이 있으면 된다 — 무엇인지 한 줄,
`npm ci && npm run dev`, 그리고 콘텐츠를 어디서 고치는지(`content/pages/*.json`).

## 넘기기 전에

```bash
npm ci
npx tsc --noEmit
npm run build
npx --package @zalkera/client zalkera-validate . --gate   # rc=0 이어야 한다
```

rc 가 **7** 이면 통과가 아니라 「검사가 안 돌았다」는 뜻이다. 특히 **`package.json` 의
`zalkera` 선언을 지워서 오류를 없애지 마라** — 지우면 관문이 `[EDECL]` 로 rc=7 을 낸다.
