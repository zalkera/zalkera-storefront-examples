# spec/ — 프론트엔드 구현 명세

**서드파티 개발자·AI 에게 그대로 주는 문서 묶음이다.** 우리 시작 소스(팩)에서 출발하지 않고
새로 짜는 경우를 위한 자리다.

| 문서 | 누구에게 | 무엇을 |
|---|---|---|
| [`storefront-spec.md`](storefront-spec.md) | 새로 짜는 사람·AI | 잘커라 위에서 도는 프론트엔드를 어떻게 만들어야 하는가 |
| [`handoff/`](handoff/) | 이미 받은 소스를 고칠 사람 | 그 소스의 규약 위반과 정정 방법 |

## 이 디렉터리의 규율

- **기술 규범만 담는다.** 사업·요금·법무·콘텐츠 정책은 여기 없다.
- **판정은 문서가 아니라 기계가 한다.** 규칙마다 검사기 규칙 ID 를 같이 적는다 —
  의심스러울 때 무엇을 돌려 확인할지 알려 주기 위해서다.
- **종수·판번호를 세지 마라.** 어휘가 늘거나 줄면 그 숫자가 거짓이 된다. 세야 하면 조회 명령을 적는다.

## 이 문서들과 `AGENTS.md` 의 차이

- **`AGENTS.md`**(레포 루트) — **이 레포를 고치는** 에이전트용. 파일 좌표표가 중심이고,
  레포가 이미 있다는 것을 전제한다.
- **`spec/storefront-spec.md`** — **레포가 아직 없는** 사람용. 빈 디렉터리에서 시작해 이것만 따라도
  게이트를 통과하도록 쓴다.

둘이 어긋나면 검사기(`npx zalkera-validate . --gate`)가 옳다.
